\chapter[Tujuan Ujian]{Tujuan Ujian}
Sesuai lembar soal Ujian Tengah Semester mata kuliah \textit{Konstruksi dan Evolusi Perangkat Lunak} Semester Gasal 2026/2027, pengerjaan ujian ini bertujuan agar mahasiswa mampu:
\begin{enumerate}
    \item Membuat backend Laravel bertema mandiri berupa RESTful API dengan login dan logout berbasis token (Laravel Sanctum), CRUD lengkap yang tersimpan di basis data, kode status 201, 422, dan 401, koleksi Postman, serta minimal dua \textit{feature test} (soal 1, CPMK 1).
    \item Membuat frontend Vue.js yang memakai API tersebut melalui Axios: login yang menyimpan token, halaman CRUD, dan alamat API yang diatur lewat variabel lingkungan (soal 2, CPMK 1).
    \item Mengelola kode di repositori publik \texttt{uts-p1-535493} dengan folder \texttt{backend/} dan \texttt{frontend/}, branch \texttt{main}, \texttt{dev}, dan branch fitur, proteksi branch yang mewajibkan Pull Request dan status check, serta \texttt{ci.yml} dengan job test backend dan build frontend (soal 3, CPMK 2).
    \item Menambahkan job deploy yang hanya berjalan pada push ke \texttt{main}, menyimpan nilai rahasia di GitHub Secrets, dan mengunggah image backend serta frontend ke \texttt{ghcr.io} dengan tag nomor commit (soal 4, CPMK 3).
    \item Menyusun Dockerfile backend dengan \textit{layer caching} Composer dan Dockerfile frontend \textit{multi-stage} berbasis Nginx tanpa \texttt{node\_modules}, lengkap dengan \texttt{.dockerignore} dan tanpa nilai rahasia (soal 5, CPMK 4 dan CPMK 5).
    \item Menjalankan seluruh sistem (basis data, backend, frontend) dengan satu perintah \texttt{docker compose up -d --build}, dengan koneksi antarservice lewat nama service, data di \textit{named volume}, dan kredensial dari \texttt{.env} yang tidak di-commit (soal 6, CPMK 6 dan CPMK 7).
    \item Menjalankan backend Laravel dengan FrankenPHP sebagai server aplikasi (soal 7, nilai tambahan).
\end{enumerate}

\chapter{Dasar Teori}

\section{Arsitektur RESTful API dan Otentikasi Token}
REST (\textit{Representational State Transfer}) memakai metode HTTP standar untuk membaca dan mengubah sumber daya. Layanan REST bersifat \textit{stateless}: setiap permintaan membawa sendiri identitas pengirimnya, tanpa sesi yang disimpan di memori peladen \cite{laravel-sanctum}.

Laravel Sanctum menerbitkan \textit{personal access token} setelah kredensial pengguna diverifikasi. Peladen menyimpan hash token di basis data, sedangkan klien menyimpan teks aslinya dan mengirimkannya pada tajuk \texttt{Authorization: Bearer <token>}. Kode status HTTP menjadi bagian dari kontrak API: 201 ketika data dibuat, 422 ketika validasi gagal, dan 401 ketika token tidak ada atau tidak sah \cite{laravel-sanctum}.

\section{Aplikasi Halaman Tunggal dan Klien HTTP}
Vue.js 3 membangun antarmuka dari komponen reaktif, sehingga tampilan diperbarui tanpa memuat ulang halaman \cite{vuejs}. Axios menghubungkan komponen dengan API. \textit{Request interceptor} menyisipkan token dari \texttt{localStorage} ke setiap permintaan, dan \textit{response interceptor} membersihkan sesi ketika peladen membalas 401. Alamat API dibaca dari variabel lingkungan agar tidak ditulis mati di komponen \cite{axios}.

\section{Manajemen Repositori Git dan Proteksi Branch}
Branch \texttt{main} menampung kode yang siap rilis, \texttt{dev} menampung hasil integrasi, dan setiap pekerjaan baru dibuat di branch fitur lalu digabung lewat Pull Request. \textit{Branch protection rules} di GitHub menolak push langsung dan mewajibkan status check lulus sebelum merge \cite{github-protection}.

\section{Otomatisasi Alur Kerja dengan GitHub Actions}
GitHub Actions menjalankan \textit{workflow} berformat YAML di \texttt{.github/workflows/} sebagai respons terhadap kejadian di repositori, misalnya push atau Pull Request. Job yang tidak saling bergantung berjalan paralel, sedangkan job dengan \texttt{needs} dan \texttt{if} hanya berjalan setelah syaratnya terpenuhi \cite{github-actions}.

\section{Kontainerisasi dan Dockerfile Multi-Stage}
Docker mengemas aplikasi beserta dependensinya ke dalam image yang berjalan sama di mesin mana pun. Setiap instruksi Dockerfile menghasilkan lapisan yang di-\textit{cache}. Dengan menyalin manifes dependensi sebelum kode sumber, langkah instalasi dependensi tidak diulang selama manifesnya tidak berubah. \textit{Multi-stage build} memisahkan tahap kompilasi dari tahap penyajian, sehingga image akhir hanya berisi hasil build \cite{docker-multistage,nginx}.

\section{Docker Compose}
Docker Compose mendefinisikan beberapa container dalam satu berkas \texttt{docker-compose.yml}. Setiap service masuk ke jaringan yang sama dan dapat saling memanggil dengan nama service sebagai nama host. Data yang harus bertahan disimpan di \textit{named volume} yang dikelola Docker dan tidak ikut terhapus oleh \texttt{docker compose down}. Nilai seperti \texttt{\$\{DB\_PASSWORD\}} di dalam berkas compose diambil dari berkas \texttt{.env} di folder yang sama \cite{docker-compose}.

\section{FrankenPHP}
FrankenPHP adalah server aplikasi PHP yang dibangun di atas peladen web Caddy. PHP berjalan langsung di dalam proses peladen, sehingga tidak perlu \texttt{php artisan serve} maupun pasangan PHP-FPM dan Nginx. Image resminya menyediakan perintah \texttt{frankenphp php-server} untuk menyajikan folder \texttt{public/} Laravel \cite{frankenphp}.

\section{Soal 2: Frontend Vue.js dan Axios (CPMK 1)}

\subsection{Alamat API dari Variabel Lingkungan (Soal 2c)}
Alamat API dibaca dari \texttt{import.meta.env.VITE\_API\_BASE\_URL} (Listing \ref{lst:vue-api-client}). Saat pengembangan, nilainya diambil dari \texttt{frontend/.env}. Saat image dibangun, nilainya dikirim sebagai \textit{build argument}; di Docker Compose nilainya \texttt{/api}, sehingga halaman login menampilkan ``Server API /api'' (Gambar \ref{fig:vue-login}).

\begin{lstlisting}[style=jsstyle,caption={Klien Axios di frontend/src/api.js.},label={lst:vue-api-client}]
import axios from 'axios';

const apiBaseUrl = import.meta.env.VITE_API_BASE_URL || 'http://localhost:8000/api';

const apiClient = axios.create({
  baseURL: apiBaseUrl,
  headers: {
    'Accept': 'application/json',
    'Content-Type': 'application/json',
  },
});

apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem('auth_token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

apiClient.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response && error.response.status === 401) {
      localStorage.removeItem('auth_token');
      localStorage.removeItem('auth_user');
      window.dispatchEvent(new CustomEvent('auth:unauthorized'));
    }
    return Promise.reject(error);
  }
);

export default apiClient;
export { apiBaseUrl };
\end{lstlisting}

\section{Alur Data dari Vue ke Laravel ke Basis Data}
Contoh alur ketika pengguna menyimpan aset baru dari peramban:
\begin{enumerate}
    \item Komponen Vue memanggil \texttt{apiClient.post('/assets', form)}. Karena \texttt{baseURL} bernilai \texttt{/api}, Axios mengirim \texttt{POST http://localhost:8080/api/assets} dengan tajuk \texttt{Authorization: Bearer <token>} dari \texttt{localStorage}.
    \item Nginx di container \texttt{frontend} mencocokkan \texttt{location /api/} dan meneruskan permintaan ke \texttt{http://backend:8000/api/assets} lewat jaringan Docker Compose.
    \item FrankenPHP di container \texttt{backend} meneruskan permintaan ke Laravel. Middleware \texttt{auth:sanctum} mencocokkan hash token dengan tabel \texttt{personal\_access\_tokens}, lalu \texttt{AssetController@store} memvalidasi data.
    \item Eloquent menulis baris baru ke tabel \texttt{assets} di PostgreSQL pada host \texttt{db}. Data fisiknya berada di volume \texttt{pgdata}.
    \item Laravel membalas 201 berisi data aset. Balasan kembali melalui Nginx ke peramban, dan Vue menambahkan aset itu ke tabel serta memperbarui angka ringkasan tanpa memuat ulang halaman.
\end{enumerate}
Jika validasi gagal, Laravel membalas 422 dan Vue menampilkan pesannya di bawah kolom terkait. Jika token tidak sah, Laravel membalas 401 dan \textit{interceptor} Axios menghapus sesi lalu mengembalikan pengguna ke halaman login.

\chapter{Kendala dan Solusi}
\begin{enumerate}
    \item \textbf{Komit langsung ke main.} Komit \texttt{f83fed0} masuk ke \texttt{main} tanpa Pull Request karena aturan awal hanya mewajibkan status check dan admin masih bisa melewatinya. Solusinya, aturan \texttt{main} dan \texttt{dev} ditambah \textit{Require a pull request before merging} dan \textit{Do not allow bypassing the above settings}. Sejak itu semua perubahan masuk lewat Pull Request.
    \item \textbf{APP\_KEY di GitHub Secrets tidak valid.} Saat \texttt{APP\_KEY} mulai dibaca dari Secrets, \texttt{Backend Test} gagal dengan pesan ``Unsupported cipher or incorrect key length''. Nilai lama ternyata salah format dan tidak terdeteksi karena sebelumnya secret itu belum pernah dipakai. Solusinya, kunci baru berformat \texttt{base64:} dengan panjang 32 byte dibuat ulang lalu disimpan ke Secrets, kemudian job dijalankan ulang.
    \item \textbf{Port 8000 sudah dipakai.} Di laptop pengerjaan, port 8000 dipakai aplikasi Python (uvicorn) lain. Port backend di \texttt{docker-compose.yml} dibuat dapat diatur lewat \texttt{BACKEND\_PORT} dengan nilai bawaan 8000, dan di laptop ini diisi 8001 lewat \texttt{.env}.
    \item \textbf{Healthcheck bawaan image FrankenPHP.} Image FrankenPHP membawa \textit{healthcheck} yang memeriksa \textit{admin endpoint} di port 2019, sedangkan \texttt{php-server} mematikan endpoint tersebut. Akibatnya backend tertahan di status \textit{health: starting}. Solusinya, \textit{healthcheck} di \texttt{docker-compose.yml} diganti dengan pemeriksaan rute \texttt{/up} milik Laravel, dan frontend menunggu backend \textit{healthy}.
    \item \textbf{Perubahan data hilang setelah down/up.} Pada uji persistensi pertama, aset baru tetap ada, tetapi status AST-LAB-005 yang diubah menjadi Dipinjam kembali ke Tersedia. Penyebabnya, seeder dijalankan setiap kali container backend start dan memakai \texttt{updateOrCreate}, sehingga data seed ditimpa ke nilai awal. Seeder diubah menjadi \texttt{firstOrCreate} yang hanya membuat data yang belum ada (Pull Request \#9), lalu uji persistensi diulang dan hasilnya sesuai (Gambar \ref{fig:persistensi}).
    \item \textbf{Koleksi Postman tidak bisa dijalankan berurutan.} Versi awal koleksi meletakkan logout sebelum CRUD sehingga token sudah dicabut, dan request ubah serta hapus memakai ID tetap \texttt{1} yang ikut menghapus data seed. Koleksi disusun ulang (Pull Request \#7): ID diambil dari respons tambah aset, logout dipindah ke akhir, dan setiap request diberi tes kode status.
\end{enumerate}

\chapter{Kesimpulan}
\begin{enumerate}
    \item Backend Laravel untuk Sistem Manajemen Aset Laboratorium melindungi seluruh rute privat dengan token Sanctum, menyediakan CRUD aset, dan mengembalikan 201, 422, dan 401 sesuai kondisinya. Perilaku ini dibuktikan oleh 13 \textit{feature test} yang lulus dan 11 request koleksi Postman yang lulus di Newman (CPMK 1).
    \item Frontend Vue 3 dengan Axios menangani login, menyimpan token di \texttt{localStorage}, dan menjalankan tampil, tambah, ubah, serta hapus dari peramban. Alamat API diatur lewat \texttt{VITE\_API\_BASE\_URL} (CPMK 1).
    \item Kode dikelola di repositori publik \texttt{uts-p1-535493}. Branch \texttt{main} dan \texttt{dev} mewajibkan Pull Request serta kelulusan \texttt{Backend Test} dan \texttt{Frontend Build}, dan aturan itu juga mengikat admin (CPMK 2).
    \item Job deploy hanya berjalan pada push ke \texttt{main}. \texttt{APP\_KEY} dan \texttt{DB\_PASSWORD} disimpan di GitHub Secrets, dan image backend serta frontend dipublikasikan ke \texttt{ghcr.io} dengan tag hash commit (CPMK 3).
    \item Dockerfile backend memasang dependensi Composer sebelum menyalin kode, dan Dockerfile frontend memakai \textit{multi-stage build} sehingga image akhir hanya berisi Nginx dan hasil build (CPMK 4 dan CPMK 5).
    \item \texttt{docker compose up -d --build} menjalankan PostgreSQL, backend, dan frontend yang saling terhubung lewat nama service. Data bertahan setelah \texttt{down} dan \texttt{up} karena disimpan di \textit{named volume}, dan kredensial dibaca dari \texttt{.env} yang tidak di-commit (CPMK 6 dan CPMK 7).
    \item Backend dilayani FrankenPHP 1.13.2 dengan PHP 8.5.12, dibuktikan oleh tajuk respons dan log container (nilai tambahan).
\end{enumerate}
